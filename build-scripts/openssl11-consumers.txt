# openssl11-consumers.txt -- reaper_verify check 22 allowlist (check_ossl_consumers.sh)
#
# In an image that carries the real OpenSSL 3.x, these are the ONLY binaries
# allowed to depend on the OpenSSL 1.1 SONAME (libcrypto.so.1.1 / libssl.so.1.1,
# supplied by the openssl11-compat shim). Anything else naming it is a stale
# build artifact that was never relinked -- the v3.0.3 hostapd -- and FAILS.
#
#   <path-in-rootfs>|closed  tracked prebuilt, shipped as a binary; may link only
#                            the 1.1 SONAME. The shim exists for these and nothing else.
#   <path-in-rootfs>|host    source-built, but links a closed DSO (libletsencrypt,
#                            libamas-utils, libasc) or absorbs prebuilt objects, so
#                            the linker needs the 1.1 name too. A rebuilt host ALWAYS
#                            also names libcrypto.so.3; one that names only 1.1 is stale.
#   <path-in-rootfs>|must3   source-built with no closed input: must name
#                            libcrypto.so.3 and must NOT name the 1.1 SONAME.
#
# Absent paths are fine (per-model blob sets; Reaper removed aaews, mastiff, asd,
# the AiCloud/AiDisk lighttpd modules and libasusnatnl -- they stay listed so a
# sibling or a future re-add is still classified). The check is inert on a 1.1 image.
#
# Ground truth: upstream's clean-room 3006.102.9 alpha1 RT-BE96U image, decomposed
# 2026-08-31 (32 consumers of the 1.1 SONAME: 28 closed, 4 hosts; 126 binaries on
# .so.3 only), cross-checked against git-tracked prebuilts in the canon tree
# (2026-09-05). Upstream links the four hosts against BOTH libraries.
