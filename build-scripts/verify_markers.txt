# v3.0.1 -- both /proc/blog/skip_wireguard_network writes carry a TRAILING SPACE.
# The kernel handler copy_from_user()s into a 128-byte stack buffer, never
# NUL-terminates it, then runs strsep(" ")/strlen over it and breaks once it has
# the ip token. The trailing space puts strsep's NUL inside the bytes we wrote,
# so the ip token is always terminated in-region. Dropping it (or reverting the
# del site to `echo`, which appends a newline instead) puts the parse back over
# uninitialised kernel stack on every WireGuard-target apply AND revert.
# NOTE the DOUBLED PERCENT. These lines are generated shell held in a C fprintf
# FORMAT string, so what lands in sbin/rc's .rodata is the format -- `%%s` --
# not the `%s` the generated script ends up carrying at runtime. Matching the
# runtime form gives x0 and fails the build (it did, on the first v3.0.1 build).
# Same trap for any marker pinning shell that rc/httpd emit through *printf.
sbin/rc|printf 'add %%s ' |1
sbin/rc|printf 'del %%s ' |1
